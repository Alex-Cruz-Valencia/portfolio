# Alex Cruz-Valencia — PM Portfolio

Personal product management portfolio site. Built with Astro 7, deployed on Vercel. Targets APM internship recruiters at large tech companies for Summer 2027.

## Stack

| Layer | Choice | Why |
|---|---|---|
| Framework | [Astro 7](https://astro.build) | Static-first, zero JS by default, markdown content built-in |
| Hosting | [Vercel](https://vercel.com) | Auto-deploys on every push to `main` |
| Fonts | Playfair Display + Inter (Google Fonts) | Editorial serif headlines + clean sans body |
| Styling | Scoped Astro `<style>` + CSS custom properties | No framework dependency, easy to override |
| Content | Astro Content Collections (glob loader) | Add a `.md` file → page appears automatically |

## Commands

```bash
npm run dev          # Start dev server at http://localhost:4321
npm run build        # Build to ./dist/ (run before deploying manually)
npm run preview      # Preview the production build locally
npm run generate:og  # Regenerate public/og.png (the social preview image)
```

### Environment variables

| Var | Purpose | Default |
|---|---|---|
| `SITE_URL` | Production URL used for canonical + Open Graph tags (`astro.config.mjs`) | current Vercel preview domain |

Set `SITE_URL` in Vercel's project settings once Alex moves to a stable or custom domain — no code change needed after that.

### Analytics

`<Analytics />` (`@vercel/analytics/astro`) is wired up in `Layout.astro`, but Vercel Web Analytics still needs to be turned on once per project: Vercel dashboard → the project → **Analytics** tab → **Enable**. Nothing is tracked until that's done.

## Adding a Case Study

1. Create a new file in `src/content/case-studies/your-slug.mdx` (`.mdx`, not `.md` — that's what lets it use `<Figure>`, `<VisualPlaceholder>`, etc.)
2. Add frontmatter — required fields plus the optional recruiter-skim block:

```markdown
---
title: "Your Case Study Title"
date: "Jan 2026"
excerpt: "One or two sentences that appear on the home page and in social previews."
tags: ["UX Research", "Prioritization"]   # optional
readTime: "5 min read"                    # optional
order: 5                                  # optional — controls home page + prev/next order
role: "Your title"                        # optional — powers the CaseSummary card
team: "Who you worked with"               # optional
timeline: "Jan – Mar 2026"                # optional
outcome: "What shipped or was learned"    # optional
keyDecisions:                             # optional
  - "First decision, one line"
  - "Second decision, one line"
---

import VisualPlaceholder from '../../components/VisualPlaceholder.astro';

## It all started when...

Your narrative here. Follow the structure:
1. Hook — open with the moment the problem became visible
2. The Hypothesis — what you believed was actually wrong
3. The Prioritization Call — what you chose to do and what you didn't, and why
4. What Was Built — brief, specific
5. The Outcome — measured if possible, honest if not
6. What This Revealed — short reflection on your PM thinking

<VisualPlaceholder label="TODO(Alex): a real screenshot or diagram goes here" />
```

Note: MDX doesn't parse `<!-- HTML comments -->` — use `{/* TODO(Alex): ... */}` inside the body instead (frontmatter is still plain YAML, so `# comment` works there).

3. The home page and routing update automatically. No code changes needed.

## Updating Personal Info

All personal details are in a small number of files:

| What | File | Field |
|---|---|---|
| Name in nav/footer/title | `src/components/Nav.astro`, `src/components/Footer.astro`, `src/layouts/Layout.astro` | Literal text / `fullTitle` |
| Bio copy | `src/pages/about.astro` | `<p>` tags in `.bio` |
| Sidebar facts | `src/pages/about.astro` | `.aside-block` sections |
| Email | `src/pages/contact.astro` | `mailto:` href + display text |
| LinkedIn | `src/pages/contact.astro` + `src/pages/about.astro` | href + display text |
| GitHub | `src/pages/contact.astro` | href + display text |
| Resume | `public/resume.pdf` | Replace the file |
| Site URL (OG/canonical) | Vercel project settings | `SITE_URL` env var (falls back to a placeholder in `astro.config.mjs`) |

## Deployment

The site auto-deploys to Vercel on every push to `main`. No manual steps needed.

Once you have a real deploy URL, set the `SITE_URL` environment variable in Vercel's project settings (see "Environment variables" above) — no code change needed. That fixes canonical URLs, Open Graph/Twitter links, and `public/robots.txt`'s `Sitemap:` line all at once (update `robots.txt` by hand, since it's a static file and can't read env vars).

## Content

- **Case studies** (`src/content/case-studies/*.mdx`) — 4 long-form studies (Evergreen, EchoStar, Design Corps LLC research, Digital NEST), ordered by the `order` frontmatter field. Each renders a `CaseSummary` card (Role/Team/Timeline/Outcome + Key Decisions) between the header and the body.
- **Projects** (`src/content/projects/*.md`) — shorter cards in the home-page "More Work" section (Youphoria, BiteBuddy, Football Initiative, Puente). Schema: `title`, `role`, `org?`, `timeframe`, `blurb`, `link?`, `linkLabel?`, `status?`, `order?`.
- **Building** (`src/content/building/*.md`) — cards in the home-page "Building" section, same shape as `projects` plus `repo?`, `stack: string[]?`, `demo?` (a video path; renders a captioned/muted/looping `<video>` when set, otherwise just the repo link).
- **Puente log** (`src/content/puente-log/*.md`) — entries for `/puente`: `date`, `title`, `assumption` (`"tool-vs-barrier" | "kids-want-role" | "nonprofit-commitment"`), `finding`, `changed`. Empty right now — the page shows "First conversations are underway — updates land here." until entries exist.
